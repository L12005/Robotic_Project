- 项目介绍：
	- 项目背景：
		- 在狭窄走廊和电梯口，配送机器人和人相遇时，常常不会主动退让，也不会传达“我要通过”或“我在让你”的意图，这会影响通行效率和交互体验。
	- 我们的落脚点：
		- 我们希望做一个仿真系统，让机器人在狭窄空间中遇到人时，能够主动选择退让，并在后退过程中进行避障。
	- 项目目标：
		- 不是做完整落地系统，而是做一个可演示、可比较的仿真 demo，验证“主动退让”比“原地等待”更合理。
	- 项目方法：
		- 使用ROS2 Humble + Gazebo11做仿真，先做状态机和规则驱动，不做复杂算法和强化学习
	- 最小成果：
		- 先完成一个“走廊会车”场景：人和机器人相向而行，机器人检测冲突后后退让行，避开后方障碍，等待人通过，再恢复前进。
-
- 环境搭建：
	- Ubuntu： 24.04（Noble）
	- ROS2：Jazzy
	- Gazebo： Harmonic（LTS）
-
- 系统结构：
	- hmi_behavior:
		- 控制逻辑、状态机、退让算法
	- hmi_bringup:
		- 总启动文件
	- hmi_elements:
		- 机器人、人、障碍物模型
	- hmi_world
		- world场景文件
	- hmi_interfaces:
		- 自定义消息接口
-
- 技术栈：
	- ROS版本： ROS 2 Humble
	- 仿真平台： Gazebo11
	- 功能包： ament_python
	- 接口包： ament_cmake
	- python包管理：
		- setup.py 注册节点
		- package.xml 依赖管理
-
- 第一阶段目标：
	- Gazebo能启动场景
	- 配送机器人能生成
	- 人模型能生成
	- 机器人能接受控制指令
	- 能完成最简单的前进、停止和后退
	- 能搭建出状态机骨架
-
- 项目最小场景：
	- 直线走廊会车
-
- 机器人行为逻辑（需要进入条件、推出条件、状态输出、超时/异常处理）
	- Normal Move
	- Human Detected
	- Yield Backward
	- Waiting
	- Resume
-
- 机器人和人的简化规则：
	- 人以固定速度前进
	- 人是否再冲突时停下
	- 机器人退让距离
	- 后方障障碍先按什么规则检测
	- 第一版只处理静态障碍物
-
- 模型和场景参数：
	- 配送机器人长宽高
	- 碰撞体形状
	- 走廊的宽度和长度
	- 障碍物尺寸
	- 人和机器人的初始位置
-
- 协作约定：
	- 坐标系统一：
		- 在 world 坐标系下表达 pose
	- 朝向统一：
		- yaw
	- 单位统一：
		- 距离 m； 速度 m/s； 角速度 rad/s
	- 话题命名：
		- 全部使用hmi前缀
	- 发布频率同一：
		- 动态对象10Hz，静态对象
-
- 分工方案：
	- 模型、场景负责人：
		- 负责： hmi_elements、 hmi_world
		- 任务：
			- 搭建走廊 world
			- 生成人模型、机器人模型、静态障碍物
			- 周期发布 robot_state / human_state / obstacle_state
		- 需对外保证的数据：
			- 机器人位置
			- 机器人朝向
			- 机器人线速度、角速度
			- 人的位置
			- 人的朝向
			- 人的线速度、角速度
			- 障碍物位置和尺寸
	- 控制负责人：
		- 负责： hmi_behavior
		- 任务：
			- 订阅 robot_state / human_state / obstacle_state
			- 根据规则判断是否进入 Human Detected / Yield Backward / Waiting / Resume
			- 发布 /hmi/control/cmd_vel
			- 发布 /hmi/control/behavior_state
		- 明确使用的数据：
			- 人与机器人之间的相对距离
			- 人与机器人是否正向会车（默认会）
			- 机器人后方是否存在静态障碍物
			- 人是否已经通过机器人
	- 系统集成负责人：
		- 负责： hmi_bringup
		- 任务：
			- 写统一 launch 文件
			- 保证话题名、坐标系名、启动顺序一致
			- 状态切换是否能在终端中观察到
	- 接口负责人：
		- 负责：hmi_interfaces
		- 任务：
			- 建好 msg 文件
			- 在 CMakeLists.txt / package.xml 中注册接口依赖
			- 给所有同学输出统一接口说明表
		- 请避免：
			- 字段命名频繁变化
			- 一个阶段内多次改 topic 名
	- 文档负责人：
		- 任务：
			- 维护接口表
			- 维护状态机转移表
			- 维护参数表
			- 记录每个包当前完成度和测试结果
			- 方便组里知道现在进度！！！
			-
-
- 话题流向：
	- /hmi/scene/robot_state
		- 发布方：场景/仿真同学
		- 订阅方：控制同学
		- 用途：把机器人当前位姿和速度发送给状态机
	- /hmi/scene/human_state
		- 发布方：场景/仿真同学
		- 订阅方：控制同学
		- 用途：把人当前位置和速度发送给状态机
	- /hmi/scene/obstacle_state
		- 发布方：场景/仿真同学
		- 订阅方：控制同学
		- 用途：把后方静态障碍物的位置发送给状态机，供后退避障判断
	- /hmi/control/cmd_vel
		- 发布方：控制同学
		- 订阅方：机器人底盘/仿真执行侧
		- 用途：输出机器人前进、停止、后退的速度命令
	- /hmi/control/behavior_state
		- 发布方：控制同学
		- 订阅方：集成同学、文档同学、后续可视化同学
		- 用途：输出当前状态机状态，便于调试和录屏展示
-
- 接口定义：
	- ActorState.msg：
		- std_msgs/Header header 时间戳
		- string actor_id
		- string actor_type
		- float32 x
		- float32 y
		- float32 yaw
		- float32 linear_x
		- float32 angular_z
		- bool is_moving 判断目标是否静止
	- ObstacleState.msg：
		- std_msgs/Header header
		- string obstacle_id
		- float32 x
		- float32 y
		- float32 width
		- float32 length
		- bool is_static 目前默认true
	- BehaviorState.msg：
		- std_msgs/Header header
		- string current_state
			- NormalMove / HumanDetected / YieldBackward / Waiting / Resume
		- string reason
			- human_close / obstacle_back / human_passed
		- float32 target_linear_x
		- float32 target_angular_z
